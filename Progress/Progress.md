# Progress Status Index

> Use this table for both pending topics and decision history. Keep detailed background, conclusions, and rejected alternatives in the linked records.
> Add a pending draft topic with `—` in the Record column. Replace that marker only after a human-confirmed decision has been archived.
> If only some entries in a monthly draft have been processed, keep separate rows for pending topics and archived decisions. Do not mark the entire file as processed or move unresolved entries into a later month.
> Source references identify the file, entry date, number, and topic scope. Legacy daily-draft paths remain valid.
> The same applies within a topic: track each unresolved sub-scope in its own pending row instead of mentioning it only in a confirmed record's Notes.

> Exact status values: `Pending discussion`, `Confirmed, pending implementation`, `Implemented`, `Rejected`, `Deferred`, and `Amended by a later decision`.
> A rejected or deferred topic must link to its human-confirmed decision record instead of remaining pending. If later accepted, change the old row to `Amended by a later decision`, identify the new record in Notes, and add a new row for the newly confirmed scope.
