# Decision Record: <Topic>

- Source: `Drafts/YYYYMMDD_sequence.md` (identify the topic), or “No corresponding draft; raised directly in conversation”
- Archived: YYYY-MM-DD
- Status: Confirmed, pending implementation / Implemented / Amended by a later decision

> This is a reference template, not a form that must be filled mechanically. Keep sections that help readers understand the conclusion and remove empty ones.
> Save the completed record as `YYYYMMDD_sequence-topic.md` and update `Progress.md`. Do not write real decisions directly into this template.

## Discussion Origin

Summarize or quote the original request. This section is especially important for records arising directly from conversation because it preserves where the discussion began rather than presenting only the final proposal.

## Conclusions

List the conclusions that were explicitly confirmed, distinguishing settled points from unresolved ones. If the record covers only one topic from its source draft, state that scope here.

## Rationale and Trade-offs

Record key reasoning, rejected alternatives, and why they were rejected. Remove this section if no alternatives or trade-offs need to be preserved.

## Impact on Current Consensus

Identify any README, architecture document, `AGENTS.md`, or other living document that must be updated. If this amends an earlier decision, identify the earlier record and the relationship between old and new conclusions.

## Implementation and Verification

During design, record implementation scope and pending work. After implementation, add actual verification results and the limits of the evidence. Never describe a confirmed design as a verified implementation.
